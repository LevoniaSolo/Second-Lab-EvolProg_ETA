# Лабораторная работа №2 — вариант 17

**Тема:** генетический алгоритм для дискретной задачи с ограничениями.
**Задача:** назначение 30 задач на 5 процессоров с минимизацией максимальной загрузки.

## Как запустить в VS Code

Откройте папку `LR2_variant17` в VS Code и выполните в терминале:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install matplotlib
python main.py
```

На Windows может использоваться `python` вместо `python3`.
Для короткой проверки: `python3 main.py --quick` (3 запуска по 800 оценок; **не для отчёта**).
Для полноценной ЛР всегда запускайте `python3 main.py`.

Результаты сохраняются в папку `results/` (создаётся автоматически):
- `instance.json` — исходные данные и seed их генерации;
- `examples.csv` — 2 допустимых и 2 недопустимых назначения;
- `runs.csv` — результаты всех запусков и их seed;
- `summary.csv` — статистика best/mean/median/std/worst;
- `best_solution.json` — распределение задач по процессорам;
- `convergence.png`, `boxplot.png` — графики.

## Математическая постановка

Задача `i` имеет длительность `t[i]`. Генотип `x` — вектор из 30 целых чисел, `x[i] ∈ {0,1,2,3,4}` — индекс процессора. Декодирование: группировка задач по `x[i]` и суммирование длительностей.

`L[p] = sum(t[i] for i if x[i] == p)`.

Минимизируем `Cmax(x) = max_p L[p]` при ограничениях:
1. каждая задача назначена ровно одному процессору (гарантировано кодировкой);
2. `L[p] <= 67` для каждого процессора;
3. обязательные назначения: задача с индексом 0 → CPU 0, индекс 7 → CPU 2, индекс 19 → CPU 4 (в `best_solution.json` номера задач указаны **с единицы**, поэтому это задачи 1, 8 и 20).

Длительности генерируются из целых чисел 3..15 с `random.Random(17026)`; вместимость = `ceil(sum(t)/5*1.35)`, в этом наборе 67. Обязательные назначения и множитель 1.35 — **самостоятельно выбранные условия модели**, методичка не задаёт их численно. Это позволяет проверять обе формы ограничений без чрезмерного усложнения.

## Генетический алгоритм

- Популяция 80, бюджет 8000 **оценённых кандидатов** на запуск (включая начальную популяцию, без повторного учёта элиты).
- Турнирная селекция (3 кандидата), равномерный кроссинговер (`Pc = 0.9`).
- Мутация с вероятностью `Pm = 0.3`: **move** — назначить одну задачу другому процессору; **swap** — обменять процессоры двух задач.
- Элитизм: 2 лучших особи по используемой функции приспособленности.
- Стратегия **repair**: восстановить обязательные назначения, перенести задачи с перегруженных процессоров; при неудаче — построить допустимое назначение жадно заново.
- Стратегия **penalty**: `fitness = Cmax + 20*sum(max(0,L[p]-cap[p])) + 1000*число_нарушений_обязательных_назначений`. Допустимость не навязывается, но лучшим ответом признаётся **только допустимая** особь.
- Сравнения: `GA_repair_move` vs `GA_penalty_move` (только стратегия ограничений), `GA_repair_move` vs `GA_repair_swap` (только мутация).
- Базовая линия `Random_feasible`: 8000 случайно сгенерированных и отремонтированных кандидатов на запуск. Единица бюджета — **одна оценка решения**, а не равное процессорное время; ремонт сам по себе может требовать разного количества операций.
- 20 запусков на конфигурацию; seed ГА: 10000..10019, базовая линия: 20000..20019.
